- (decision) Why: owner wants the app to open on a wallet chooser (one card per Seed) so wallets are created, opened, renamed, removed there; per-wallet things leave app-level Settings. Pain + vision; real Mainnet funds raise the cost of any defect.
- (capability) CAP-1 Chooser is the first screen on every launch: one card per Seed, stored order, no ledger read, no balances (AD-32, AD-36, AD-43). Success: cold start at any path shows the chooser at /; a test mounting it with several open locks leaves the query cache empty and never calls getXrplClient.
- (capability) CAP-2 Gate has three outcomes; a failed wallet-list or hydration read shows the error state with Retry, never Onboarding or an empty chooser (AD-37). Success: forced vault-read rejection renders 'The wallets on this device could not be read. Nothing was changed.' with Retry, mounts neither Onboarding nor the shell, and calls no store setter; Retry after success reaches the chooser; zero-wallet success reaches Onboarding.
- (capability) CAP-3 User can open a wallet from its card (AD-34, AD-43, AD-32). Success: Open on a locked card shows the existing Unlock view; after unlock a single-view Seed lands in its shell, a multi-view Seed returns to the chooser with the card open; a network row opens exactly its view; a Mainnet view is never entered by default; creating a wallet never selects it.
- (capability) CAP-4 User can leave a wallet for the chooser without closing its lock (AD-33, AD-38, AD-34). Success: Wallets key and browser Back land on the chooser with focus on the Wallets h1, no ping-pong; the wallet's lock is still open; its account-scoped query data is removed; a blocked screen disables the Wallets key with visible reason; that wallet's notices clear.
- (capability) CAP-5 One card per Seed with a row per network; a locked card is its name and nothing else, enforced by type (AD-43, AD-26, AD-36). Success: the locked card type has no address, network, Node or check-kind field; a locked card renders name, Locked lamp+word and 'Locked.' only; open card rows show network word, stamp (Real funds, Not stable) and AddressLink with explicit network; order follows Seed createdAt, never state.
- (capability) CAP-6 User can rename a wallet, local to the device (AD-41, AD-42). Success: Rename dialog validates 1-40 chars, case-insensitive uniqueness against other Seeds, with the UX strings; Save writes the Seed record without bumping rev or asking a lock; all network rows show the new name; a failed write shows 'Could not rename the wallet. Nothing was changed.' and keeps the dialog open; nothing reaches the ledger.
- (capability) CAP-7 User can remove a wallet or one network view from the chooser (AD-46, AD-16). Success: Remove works only with the wallet's own lock open, re-checked at call time even if aria-disabled is bypassed; locked card shows 'Open this wallet to remove it.'; dialog picks one of three bodies (sibling view, sole view, last wallet); teardown goes through lib/teardown.ts; activeWalletId never points at a removed wallet; last removal returns to Onboarding.
- (capability) CAP-8 User can add a wallet from the chooser, by Generate or Import, with every lock closed (AD-39, AD-40, AD-28, AD-3, AD-22). Success: Import creates its own lock and Open Check through keystore.importStoredWallet, refuses Open Check none, applies the Mainnet floor, shows the written-Seed confirm exactly as Generate on Mainnet, refuses a Seed whose address already exists on the device before any prompt or ledger read; neither path enters the wallet; the new card appears focused with 'Wallet added.'
- (capability) CAP-9 Each open wallet has a Configure screen at /wallets/:id/configure holding Checks, Seed, Operating another account, Other networks, Node, Two-device signing (AD-32, AD-44). Success: reachable only with the lock open (else resetToHome); Edit checks, Reveal seed, Let another wallet sign, Use on {Network}, Sign with two devices, Node all work from it with shipped dialogs and focus return; their Back returns to Configure; Settings no longer holds them.
- (capability) CAP-10 Auto-lock is edited on the Checks plate through the one writer that re-proves the Open Check (AD-44, AD-28). Success: changing minutes re-prompts the lock's Open Check, enforces the Mainnet floor across every wallet on the lock, invalidates lockInfo, and a lock shared by several Seeds says so with the count.
- (capability) CAP-11 Settings is app-level only: Address book, Version and updates, Remove all wallets from this device (AD-44, AD-45, AD-46). Success: no per-wallet control, no Lock now, no auto-lock; reachable from the chooser Settings key and the in-wallet Settings tab (same component, never both mounted); Remove all works with no wallet or open lock, including for a hard-locked user.
- (capability) CAP-12 Header splits into a chooser header and a wallet header; the wallet picker Select is removed; Lock closes through the teardown owner; update marker is one shared predicate (AD-45, AD-33). Success: wallet header shows Wallets key, and only for an open lock NetworkPlate, Configure, and Lock when Open Check is not none; locked wallet header is the Wallets key alone; Lock key calls tearDownLock then leaveToChooser; chooser Settings key name reads 'Settings, update available' when an update waits, never a modal or redirect, and a declined release does not relight it.
- (capability) CAP-13 Activity timer scoping and lifecycle hooks (AD-31, AD-35, AD-16). Success: useAutoLock and useClearCacheOnLock mount once in the app shell above the route switch, running on the chooser; touchLock(null) extends no in-memory expiry, timer or persisted session; chooser activity never extends any lock; backgrounding and expiry still close locks on every route.
- (capability) CAP-14 Open card has its own Lock key (when the Open Check is not none) and states why when absent (AD-45, AD-38, EXPERIENCE state patterns). Success: Lock flips the card (and any card on the same lock, with a note naming them) to Locked in place via tearDownLock, announced in a polite live region; with Open Check none the line 'No Open Check: this wallet opens itself, so there is nothing to lock.' is visible.
- (constraint) No secret in localStorage, React state, store, URL or anything serializable. Routes carry a screen name and at most a walletId; never a name, seed, lock id or form data (AD-32, CLAUDE.md). Seed lives only in a ref passed as a parameter to keystore and cleared in finally (AD-3, AD-39).
- (constraint) A locked wallet is its name and nothing else: no address, network, Node or check kind, and no hook reading for it (AD-26, AD-43). Consequence accepted: a locked Mainnet card is indistinguishable from a Testnet one until opened.
- (constraint) Chooser side (chooser, /settings, add-wallet, header) mounts no ledger read, no useActiveWallet/useActiveNetwork/useActiveNode, no NetworkPlate and no account-scoped key (AD-36, AD-4). Any device-scoped read is a named exception on the key factory.
- (constraint) A failed read is never rendered as empty or current and never relaxes a guard: Gate error is its own surface (AD-37, AD-13..15); aria-disabled is presentation, the handler re-checks (AD-33, AD-46).
- (constraint) Every lock close, leave and remove goes through lib/teardown.ts; no inline closeLock or queryClient.clear (AD-16, AD-38, AD-45, AD-46).
- (constraint) Money stays strings/BigInt; the chooser shows no balance; never Number() a drops value (CLAUDE.md, money.md).
- (constraint) Touch targets at least 44px on coarse pointers for every key, icon key, radio and checkbox row; two keys in a network row never closer than their hit areas.
- (constraint) Nothing styles :focus; outline-none banned. Focus lands: chooser h1 after leaving or Remove; new card h2 after Add; opener after a dialog; main region on entering a wallet; one h1 per screen.
- (constraint) Colour never alone: lock state = lamp+word; Mainnet = word + 'Real funds' stamp; Devnet = word + 'Not stable' + DEVNET_NOTICE; Active = word; disabled Remove = visible reason. bun run check:contrast stays green; no new colour token (DESIGN.md).
- (constraint) Both creation paths and Add wallet never call setActiveWalletId or navigate into the wallet; activeWalletId means last chosen to open, one selection field (AD-34, AD-40, AD-6).
- (constraint) Launch always lands on the chooser: rewriteBootLocation runs before first render and rewrites any non-/ path (AD-32). Back from a wallet is the chooser, from the chooser leaves the app (AD-33).
- (constraint) Policy: Import refuses Open Check none on every network; Mainnet floor (Open Check required, auto-lock at least 1 minute) and written-Seed confirm apply to import (AD-39, AD-28).
- (constraint) Name rule lives in one pure function lib/wallet-name.ts; label is local, never in the URL or ledger; existing duplicates grandfathered (AD-42). No copy may promise a passkey's authenticator name changes on rename (AD-41).
- (constraint) Updates are never automatic; the update marker is never a modal or redirect (CLAUDE.md, AD-45). Licence copy never says open source.
- (constraint) Existing query keys include active wallet and network; the factory stays the one source (AD-4); each of AD-31, AD-35, AD-36, AD-37, AD-39 gets a test that fails when the rule is removed (architecture convention). Gates: lint, build, test, check:contrast.
- (decision) Non-goals: no balances on chooser; no Mainnet badge on locked cards; no change to legacy-lock/first-run Onboarding import (Q6); no App PIN change (Q7); no change to shared-lock auto-lock semantics (Q5); no automatic updates; no exchange/swap/fiat/staking/KYC; no per-row Configure on multi-view cards; no incoming-payment notices on the chooser; no quick-switch picker, swipe, drag or overflow menu.
