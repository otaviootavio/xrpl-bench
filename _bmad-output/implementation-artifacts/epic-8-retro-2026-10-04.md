### Process lessons

- **P1: One fresh-context reviewer was load-bearing.** It found a double-pay path that the story's own acceptance criterion had introduced (F1), and that the build session's mutation table could not see, because every mutation checked a guard the spec asked for. Without round 1, epic 8 would have shipped a money defect into the send path.
- **P2: The resolver routed only blocking findings.** The reviewer's non-blocking teardown note (F2) went to neither a fix nor the ledger, although the reviewer said where it belonged. Non-blocking review notes have no forced destination.
- **P3: The epic ran ahead of the triage meant to inform it.** Epic-5 retro item 10 asked for `deferred-work.md` to be triaged before epic 6. That triage landed in #34, after #33. Its top item, the backup node answering `account_tx` with partial history (High), was proposed "as the first story of epic 8" (`deferred-work.md:161`) when epic 8 had already merged. It is still open on `dev`: `fetchAccountTx` sends `ledger_index_min: -1` and never reads the returned range (`reads.ts:176`).
- **P4: A non-UI runtime change was verified only through its seam.** The browser-pass definition of done is for UI changes, so it does not apply here, and nothing replaced it. The spec named the gap honestly. A scripted live check closed it in one run during this retrospective (Behavior verification), which shows the check is cheap enough to belong in the definition of done for runtime changes.
