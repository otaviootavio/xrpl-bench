- (direction) Otavio delegated the key-hierarchy call ('decide it for me'); decision below is mine, shown to him for veto
- (decision) Key hierarchy: a random Open Key per open-lock, wrapped under that lock's Open Check credential with a (lockId, 'open') domain-separated derivation. New Wallets always get their own lock. Session holds one non-extractable Open Key per unlocked lock with its own expiry (per-Wallet auto-lock). Prevents: a shared group key that keeps a Wallet openable after its own auto-lock fired
- (decision) Signing Check: a Wallet with one has its Seed encrypted under a random Signing Key wrapped ONLY under the signing credential, derivation domain (walletId,'sign'). The Signing Key never enters session state, a store, or the IDB session store. A Standard Wallet's Seed is encrypted under its Open Key. Prevents the for-show prompt FR-67 forbids
- (decision) App PIN: one PBKDF2 over the PIN with a device salt; per-lock and per-purpose keys via HKDF info (lockId|walletId, purpose). One PIN entry can derive several keys but never one from another. Proof stays decryption of the wrapped key; the shared failure count (FR-68) lives with the PIN, not with a lock
- (decision) Passkey PRF salts and HKDF info strings are frozen per (walletId, purpose) at creation and stored with the record; never recomputed from a constant that could change. Prevents a refactor silently losing a Passkey-Derived Seed
- (decision) Passkey-Derived Seed: Seed = xrpl Wallet.fromEntropy(HKDF(PRF(salt 'seed'|walletId)), {algorithm}). Proven by the derived address equalling the stored address. Conflicts with CLAUDE.md 'proven by decrypting known ciphertext' wording - to be amended, not bypassed: the address match rejects a wrong passkey as decryption would
- (decision) Open Check 'none' (Testnet/Devnet only): the Open Key is stored as a non-extractable CryptoKey in IDB, permitted by parent AD-5's handle rule; it is never allowed on Mainnet
- (decision) Migration FR-74: existing Wallets share one legacy open-lock whose Open Key IS today's vaultKey, wrapped as today under PIN and passkey. Zero re-encryption on update. A Wallet leaves the legacy lock only via FR-73 (edit checks), which re-encrypts that Wallet alone. Migrated Wallets lock together, as they do today
- (direction) Otavio delegated again; switching to: I decide the remaining architecture calls and log them, he reviews the draft. Product-level conflicts (FR-76, production origin gate) are NOT decided by me - asked with the draft
- (decision) Wallet identity: a Wallet is (network, Account address). The key's own derived address is stored as keyAddress (fingerprint) only. Every read, query key, Address Book entry and on-screen address uses the Account address. Signing with keyAddress != Account uses Wallet.fromSeed(seed,{algorithm, masterAddress}). Prevents: two builders keying balances on the key address vs the Account after FR-75
- (decision) Network and Node are fields of the Wallet record, set at creation. app-store's app-wide 'network' is removed; the active network is derived from the active Wallet (amends parent AD-6). Query keys stay (name, network, Account address) - the Node is not in the key, because two Nodes of one network serve one ledger
- (decision) Connection pool keyed by Node URL, not NetworkId. A custom Node is accepted only after server_info answers with the network_id of the chosen Network (0/1/2). Failover only within the built-in list. The AD-12 seam (substitute + reset) moves with the pool
- (decision) Egress (amends parent AD-2): the closed list becomes built-in Nodes, the Devnet faucet in lib/xrpl/faucet.ts, the Release Manifest, plus one new category - a user-declared Node, which exists only on a Wallet record after passing the connection test. No other user-supplied host is ever contacted
- (decision) Signing path (tightens parent AD-3): no signer and no Seed leaves lib/crypto. keystore exposes signForWallet(walletId, unsignedTx, prompts) -> signed blob, and runs that Wallet's Signing Check itself; the PIN is collected through a prompts callback (parent AD-1 shape). unlockWalletForSigning is removed. revealSeed runs the same check (FR-69). Prevents a screen that signs without the check
- (decision) Authority for check configuration: the vault record in lib/crypto/db (Seed method, algorithm, keyAddress, Open/Signing check kinds, lock id, salts) is the one owner. app-store persists only display meta derived from it (label, network, node, Account address, check kinds). Prevents the UI and the keystore disagreeing about whether a Wallet has a Signing Check
- (decision) Teardown (amends parent AD-16): a third scope, per-lock. A lock's auto-lock or manual lock drops that lock's session key and removes the account-scoped query data of its Wallets. A PIN hard lock disables PIN derivation; it never wipes the vault while a passkey-only Wallet exists. Full reset unchanged
- (decision) Rollback safety: no IndexedDB version bump. New data lands as additive fields on existing records and new keys in the existing 'vault' store (lock:<id>). Legacy Wallets keep encryptedSeed under vaultKey, so a prod rollback degrades only Wallets created or edited on the new build, never legacy ones. app-store persist version stays 0, normalised in merge (Epic 9 precedent)
- (decision) Two-device signing: one codec module owns both QR payloads (unsigned: version, network_id, tx JSON; signed: tx_blob). The online side sets LastLedgerSequence explicitly to validated + 75 and, before submitting, decodes the blob and refuses it unless its fields equal what it sent and it signs for the expected Account. Submission still goes through submitAndClassify (parent AD-9)
- (decision) Master-key state (FR-77) and Regular Key presence are read from account_info through the AD-4 factory, never stored; a guard on disabling the master key fails closed per parent AD-13
